Isabella’s V2 · Tabler y experiencia editorial

26 de octubre de 2026 · Rama version/2-simple · Implementación local, sin commit ni publicación.

Solo Isabella’s V2. No se modificaron Boccantina ni V1. Las pruebas usan catálogos temporales y fotografías identificadas como ilustrativas; no cambian datos del restaurante.

Decisiones y alcance

  • Tabler Core 1.7.1, MIT, gratuito. CSS servido localmente, versión exacta y licencia incluida. Sin Tabler Pro ni servicios de pago. No se migró el proyecto a React.
  • Productos, categorías y personal comparten controles de Tabler y una capa administrativa aislada. Lista/editor en escritorio; vistas enfocadas en móvil.
  • Guardar se habilita por cambios reales. Revertir los valores devuelve el estado limpio. Hay descarte explícito, estado de carga y confirmación accesible al abandonar un borrador. Los errores y conflictos conservan lo escrito.
  • La carta Journal usa ES/EN. Detecta el navegador y conserva la elección manual. Los datos históricos DE/AR/HE permanecen intactos; no se generan nuevas traducciones en esos idiomas para V2.
  • Inglés automático con Argos local gratuito y revisión manual de nombre/descripción. Las traducciones automáticas requieren revisión editorial.
  • Fotografía propia, detalle opcional por producto y disponibilidad diaria. El detalle es de pantalla completa en móvil. No se asignaron fotografías de otros platos a productos reales.
  • Índice de categorías sin select visible, navegación por gesto horizontal, teclado y botones persistentes. El gesto vertical mantiene el scroll.
  • Avisos ES/EN editables; movimiento opcional, pausa y respeto a movimiento reducido.

Carta física

“Avisos de la carta” incluye el enlace público y el QR descargable en SVG. Solo admite HTTPS público: rechaza direcciones locales. Al configurar el enlace, las nuevas ediciones PDF incluyen un QR. No se ha configurado una dirección de producción ni publicado esta entrega. El PDF de prueba usa example.org/isabella-qa, exclusivamente para verificar el flujo.

El módulo Menú impreso toma el mismo catálogo guardado que la carta digital. La vista previa refleja los cambios actuales. “Generar PDF actualizado” crea una edición A4 vertical con portada, índice, capítulos, variantes y precios, diseñada para papel; no imprime una captura de Journal.

  • Los productos y categorías ocultos se excluyen. “No disponible hoy” es temporal y no cambia el PDF.
  • Se conserva fecha, autor, revisión e idioma. El historial permite descargar ediciones anteriores sin sobrescribirlas.
  • El contador compara el contenido publicable: incorporaciones, modificaciones y retiradas de categorías/productos.
  • Solicitudes repetidas del mismo contenido reutilizan la edición. Una revisión obsoleta devuelve conflicto. Si cambia la carta durante la generación, esa edición queda identificada como anterior.
  • Una generación fallida conserva los PDFs anteriores. El visitante solo puede descargar un PDF que corresponda al catálogo vigente en su idioma.
  • El PDF de evidencia tiene 9 páginas: sin páginas vacías, caracteres fuera del papel ni productos omitidos. El formato inicial es A4, sin imposición de cuadernillo ni perfil de imprenta.

Permisos e integración

Se conservan sesiones, contraseña, CSRF, rutas existentes y permisos de productos/categorías. Se añadieron permisos independientes isabella.content y isabella.print. El propietario puede concederlos desde Personal; las cuentas existentes no reciben esos permisos automáticamente.

Los PDFs y sus instantáneas viven en ISABELLA_DATA_DIR/print-editions, fuera de los archivos públicos. Las cargas de producto reutilizan la validación de imágenes existente con su propio permiso. No hay integración con Firebase ni cambios en V1.

Comprobaciones

  • npm.cmd run check:admin: autenticación, CSRF, permisos, revocación, CRUD, traducción ES/EN e imágenes. Comprueba conservación de idiomas históricos.
  • npm.cmd run check:preview-a: catálogo original, 55 platos, 8 categorías, cinco precios pendientes e idiomas históricos.
  • npm.cmd run check:admin-ui: estilos compartidos de acceso sincronizados.
  • npm.cmd run check:v2: navegador Chromium, 320/390/768/1024/1440; edición, errores, navegación, detalle, paginación completa ES/EN, permisos y PDFs.
  • node scripts/check-static-v2.mjs: login de demostración, persistencia y carta pública con prefijo de ruta como GitHub Pages.
  • axe: sin infracciones automáticas en Productos, detalle móvil, carta pública, ediciones impresas y Personal para las reglas WCAG A/AA seleccionadas. Esto no sustituye una auditoría manual integral ni pruebas con lectores de pantalla.

Uso local

npm.cmd install; npm.cmd run translate:setup si falta el traductor; npm.cmd run admin:setup solo para una instalación nueva; npm.cmd run serve:preview-a. La generación PDF necesita Chrome/Chromium instalado; se puede indicar su ejecutable con CHROME_EXECUTABLE_PATH. ISABELLA_DATA_DIR permite un catálogo aislado.

npm.cmd run build:pages-admin y npm.cmd run build:pages-journal regeneran la demo desde las fuentes. La demo estática no ofrece autenticación real, traducción automática ni archivo de PDFs. No se presenta como producción.
